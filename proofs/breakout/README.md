# Proof Turn Based Tactics

Generated by `npm run sw2d -- new proof-breakout --preset breakout` from the `breakout` preset
(family: puzzle-arcade). This is a **recipe**, not a finished game - see "Known preset
limitations" below for what is deliberately not implemented yet.

## How to run

```bash
npm --workspace proof-breakout run dev
```

## How to validate

```bash
npm run sw2d -- validate proof-breakout
```

Runs manifest/content schema validation, TypeScript, this game's tests, a production build,
and (when a real browser is available) a focused smoke journey.

## How to build

```bash
npm run sw2d -- build proof-breakout
```

Produces `games/proof-breakout/dist/` - a self-contained static build with no required external
network request.

## How to pack

```bash
npm run sw2d -- pack proof-breakout
```

Produces `games/proof-breakout/pack/` - the same build, with source/tests/node_modules excluded,
ready to serve from any static file host.

## Where normal game content lives

```text
NORMAL GAME WORK              FACTORY/RUNTIME WORK (do not edit from here)
content/**                    packages/contracts/**
public/**                     packages/runtime/**
themes/**                     shared system packs (packages/packs/**)
src/game-specific/**          shared controllers (packages/runtime/src/controllers/**)
```

Edit `content/game.json` (manifest, packs, bindings/accessibility defaults),
`content/tuning.json` (movement tuning - really read by this game's shell pack, not
decorative), `content/themes/**` (presentation), and `src/game-specific/**`
(this game's own mechanics) freely. This game consumes the factory's reusable packages as
local workspace dependencies; it never copies their source.

`src/game-specific/packConfig.ts` is where packs that declare `configSource: 'code'` get
their configuration - config that carries functions, which `content/game.json` cannot express
(`sw2d.puzzle` is the one such pack today). If this preset selects one, that file ships
with a small working placeholder to replace. Every other pack is configured as JSON in
`content/game.json`.

## Composition

- Controller family/families: top-down
- Required packs (enabled by default): sw2d.arcade, sw2d.ball-paddle
- Optional packs (available, not enabled by default - add to content/game.json's systemPacks to use): none
- Content roles this preset expects: tuning, ball-paddle

`content/ball-paddle.json` is the whole game: the ball, the arena and its edge behaviours, the
paddle, the brick catalog, the wall layout and the match rules.

## Known preset limitations

- Ball/paddle serve, wall and paddle bounce, hit-location steering, brick damage, goals and match rules are reusable through sw2d.ball-paddle (arcade.ball-paddle). Collision safety is bounded substepping within the definition's declared speed range - not universal continuous collision detection; a definition beyond that range is rejected at install rather than silently tunnelling.

## How to add a level

```bash
npm run sw2d -- add-level proof-breakout <level-id>
```

Writes `content/levels/<level-id>.json` - a valid Tiled JSON export using the Phase 6
object-class subset (PlayerSpawn, Checkpoint, Collectible, Hazard, Exit, Solid). Reference it
as a content document named `levels/<level-id>`.

## How to add a theme

```bash
npm run sw2d -- add-theme proof-breakout <theme-id>
```

Writes `content/themes/<theme-id>/theme.json` - a valid local ThemeManifest. Swapping
which theme `src/content.ts` loads changes presentation only; it never changes gameplay
data.
