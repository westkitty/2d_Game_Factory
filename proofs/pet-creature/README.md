# Proof Pet Creature

Generated by `npm run sw2d -- new proof-pet-creature --preset pet-creature` from the `pet-creature` preset
(family: simulation-management). This is a **recipe**, not a finished game - see "Known preset
limitations" below for what is deliberately not implemented yet.

## How to run

```bash
npm --workspace proof-pet-creature run dev
```

## How to validate

```bash
npm run sw2d -- validate proof-pet-creature
```

Runs manifest/content schema validation, TypeScript, this game's tests, a production build,
and (when a real browser is available) a focused smoke journey.

## How to build

```bash
npm run sw2d -- build proof-pet-creature
```

Produces `games/proof-pet-creature/dist/` - a self-contained static build with no required external
network request.

## How to pack

```bash
npm run sw2d -- pack proof-pet-creature
```

Produces `games/proof-pet-creature/pack/` - the same build, with source/tests/node_modules excluded,
ready to serve from any static file host.

## Where normal game content lives

```text
NORMAL GAME WORK              FACTORY/RUNTIME WORK (do not edit from here)
content/**                    packages/contracts/**
public/**                     packages/runtime/**
themes/**                     shared system packs (packages/packs/**)
src/game-specific/**          shared controllers (packages/runtime/src/controllers/**)
```

Edit `content/game.json` (manifest, packs, bindings/accessibility defaults),
`content/tuning.json` (movement tuning - really read by this game's shell pack, not
decorative), `content/themes/**` (presentation), and `src/game-specific/**`
(this game's own mechanics) freely. This game consumes the factory's reusable packages as
local workspace dependencies; it never copies their source.

`src/game-specific/packConfig.ts` is where packs that declare `configSource: 'code'` get
their configuration - config that carries functions, which `content/game.json` cannot express
(`sw2d.puzzle` is the one such pack today). If this preset selects one, that file ships
with a small working placeholder to replace. Every other pack is configured as JSON in
`content/game.json`.

## Composition

- Controller family/families: ui-simulation
- Required packs (enabled by default): sw2d.simulation, sw2d.progression, sw2d.simulation-agents
- Optional packs (available, not enabled by default - add to content/game.json's systemPacks to use): sw2d.world
- Content roles this preset expects: tuning, agents

`content/agents.json` is the whole simulation: the needs and how fast they drift, the
behaviours and what each need pulls them toward, the preconditions that gate them, the effects
they apply, the day's schedule, and the agents themselves.

## Known preset limitations

- Needs, utility-scored behaviour, schedules, relationships and work-order reservations are reusable through sw2d.simulation-agents (simulation.agents). Need ids, behaviours and relationship metrics are all authored content - the capability assumes no vocabulary of its own. Agent presentation, and moving an agent through a particular world, stay starter-specific; pathfinding when needed is sw2d.navigation.

## How to add a level

```bash
npm run sw2d -- add-level proof-pet-creature <level-id>
```

Writes `content/levels/<level-id>.json` - a valid Tiled JSON export using the Phase 6
object-class subset (PlayerSpawn, Checkpoint, Collectible, Hazard, Exit, Solid). Reference it
as a content document named `levels/<level-id>`.

## How to add a theme

```bash
npm run sw2d -- add-theme proof-pet-creature <theme-id>
```

Writes `content/themes/<theme-id>/theme.json` - a valid local ThemeManifest. Swapping
which theme `src/content.ts` loads changes presentation only; it never changes gameplay
data.
