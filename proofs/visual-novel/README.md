# Proof Visual Novel

Generated by `npm run sw2d -- new proof-visual-novel --preset visual-novel` from the `visual-novel` preset
(family: narrative-exploration). This is a **recipe**, not a finished game - see "Known preset
limitations" below for what is deliberately not implemented yet.

## How to run

```bash
npm --workspace proof-visual-novel run dev
```

## How to validate

```bash
npm run sw2d -- validate proof-visual-novel
```

Runs manifest/content schema validation, TypeScript, this game's tests, a production build,
and (when a real browser is available) a focused smoke journey.

## How to build

```bash
npm run sw2d -- build proof-visual-novel
```

Produces `games/proof-visual-novel/dist/` - a self-contained static build with no required external
network request.

## How to pack

```bash
npm run sw2d -- pack proof-visual-novel
```

Produces `games/proof-visual-novel/pack/` - the same build, with source/tests/node_modules excluded,
ready to serve from any static file host.

## Where normal game content lives

```text
NORMAL GAME WORK              FACTORY/RUNTIME WORK (do not edit from here)
content/**                    packages/contracts/**
public/**                     packages/runtime/**
themes/**                     shared system packs (packages/packs/**)
src/game-specific/**          shared controllers (packages/runtime/src/controllers/**)
```

Edit `content/game.json` (manifest, packs, bindings/accessibility defaults),
`content/tuning.json` (movement tuning - really read by this game's shell pack, not
decorative), `content/themes/**` (presentation), and `src/game-specific/**`
(this game's own mechanics) freely. This game consumes the factory's reusable packages as
local workspace dependencies; it never copies their source.

`src/game-specific/packConfig.ts` is where packs that declare `configSource: 'code'` get
their configuration - config that carries functions, which `content/game.json` cannot express
(`sw2d.puzzle` is the one such pack today). If this preset selects one, that file ships
with a small working placeholder to replace. Every other pack is configured as JSON in
`content/game.json`.

## Composition

- Controller family/families: ui-simulation
- Required packs (enabled by default): sw2d.narrative, sw2d.dialogue
- Optional packs (available, not enabled by default - add to content/game.json's systemPacks to use): sw2d.progression, sw2d.items
- Content roles this preset expects: tuning, dialogue

`content/dialogue.json` is the whole script: the characters and their portraits by
expression, the nodes, the lines, and the choices with their conditions and effects.

Every line and choice carries a stable id distinct from its text, because text gets
translated and proofread and an id that *is* the text breaks a save the first time a typo
is fixed. Portraits name asset roles resolved through the theme, and are optional - a
zero-art build is valid.

## Known preset limitations

- Content-authored branching dialogue - characters, portraits by expression, stable line and choice ids, bounded conditions and effects, once-choices, history and save/restore - is reusable through sw2d.dialogue (narrative.dialogue), with a semantic-DOM presentation in the runtime whose full line text reaches the accessibility tree immediately. Conditions and effects are closed unions rather than an expression language, so anything a game wants that is not one of the seven condition kinds or six effect kinds stays game-specific. No localisation platform, voice-over pipeline or branching-graph visual editor ships with this.

## How to add a level

```bash
npm run sw2d -- add-level proof-visual-novel <level-id>
```

Writes `content/levels/<level-id>.json` - a valid Tiled JSON export using the Phase 6
object-class subset (PlayerSpawn, Checkpoint, Collectible, Hazard, Exit, Solid). Reference it
as a content document named `levels/<level-id>`.

## How to add a theme

```bash
npm run sw2d -- add-theme proof-visual-novel <theme-id>
```

Writes `content/themes/<theme-id>/theme.json` - a valid local ThemeManifest. Swapping
which theme `src/content.ts` loads changes presentation only; it never changes gameplay
data.
